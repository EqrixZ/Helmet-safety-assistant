# Contract changes

(Subagents append deviations from CONTRACT.md here — one bullet per change, with the reason.)
- (backend-api) `POST /api/chat/suggestions` also accepts an optional body field `{"event_id": "EVT-0012"}`. When given, the first of the 5 questions becomes a pre-filled question about that event (404 `NOT_FOUND` if the id is unknown). `{}` behaves exactly as specified. This is a backward-compatible extension so the UI can offer "ask about this event".
- (backend-api) Unknown HTTP methods on an existing route return HTTP 405 with code `BAD_REQUEST` in the standard error envelope, because the contract has no 405 code.
- (integrator) Added `GET /api/detect/model-info` → `{path: string, source: "local"|"downloaded", family: string|null, class_names: string[], class_mapping: {[className]: "hardhat"|"no_hardhat"}, fallback_repo: string, fallback_file: string}`. The detector uses the self-trained YOLO26s at `backend/models/best.pt` (classes Head/Helmet) and never contacts Hugging Face when it exists; the HF model is a fallback only. Class names are read from `model.names` at runtime and mapped via `CLASS_MAP` in `backend/detector.py` (CONTRACT §3 hardhat/no_hardhat columns unchanged). First call loads the model; failures return 500 `INTERNAL_ERROR`.
- (integrator) `events.csv` gains two trailing columns: `no_hardhat_max` (int, raw max Head count per frame before voting) and `no_hardhat_ratio` (float 0–1, share of sampled frames with >=1 Head box). `violation` is now true iff that share >= `VIOLATION_FRAME_RATIO` (default 0.4), and `no_hardhat` is the max count only when the clip is a violation (else 0), so `violation == (no_hardhat > 0)` still holds. Per-class thresholds: Helmet uses `CONF_THRESHOLD` (0.35), Head uses `HEAD_CONF_THRESHOLD` (0.55). `Event` gains `no_hardhat_max: number` and `no_hardhat_ratio: number | null` (null for logs without the columns, e.g. the sample). `ModelInfo` gains `thresholds: {hardhat, no_hardhat}` and `violation_frame_ratio`. CLI: `--head-conf`, `--vote-ratio`, `--compare` (writes `DATA_DIR/model_comparison.csv`).
- (integrator) LLM rate-limit handling in `backend/llm.py`: client throttle `LLM_RPM` (default 4/min per provider), retry up to 5 attempts on 429/503 with 2/4/8/16 s backoff or `Retry-After`, optional fallback provider `LLM_FALLBACK_API_KEY`/`_BASE_URL`/`_MODEL` (primary skipped for 60 s after it gives up). `Health` gains `llm_provider: {name: "primary"|"fallback", model, base_url} | null`, `llm_fallback_configured: boolean`, `llm_rpm: number`. `eval_results.csv` gains `provider`, `model`, `retries`, `waited_s`, `elapsed_s`.
- (integrator) Chat context is now question-aware (`backend/retrieval.py`): aggregates always; ≤15 relevant log rows as labelled lines (fallback: 10 latest violations); top-5 regulation paragraphs by character-trigram TF-IDF. `ContextSources` gains `regulation_paragraphs: string[]`, `regulation_paragraphs_total: number`, `log_rows: number`, `log_filter: string`, `token_estimate: number`; `regulation_files` now lists only files of the included paragraphs. Zone display label for `crane` changed from "พื้นที่เครน" to "โซนเครน" (CONTRACT §2 list). Reports get pandas trend labels, retrieved regulation paragraphs, and Thai-only zone names in tables. `eval_results.csv` gains `token_estimate`, `prompt_tokens`.
- (backend-api) Thai/English language support: `ChatRequest`, `SuggestionsRequest` and `ReportRequest` gain optional `language: "th"|"en"` (default `"th"`, so existing clients are unchanged; other values → 422 validation error). `"en"` gives an English chat system prompt (same data context), 5 English suggested questions, and English reports (title, headers, 5 section headings `Executive summary` / `Violations by zone and time` / `Notable events` / `Risk assessment` / `Recommendations`, tables, trend wording, English zone names such as "Crane zone", Gregorian dates). `Report` and `ReportMeta` gain `language: "th"|"en"`. New reports are saved as `report_{daily|weekly}_{YYYY-MM-DD}_{th|en}.md` (Thai and English reports for the same date coexist); legacy `report_{type}_{date}.md` files are still listed and fetchable via `GET /api/reports/{name}` with `language: "th"`.
